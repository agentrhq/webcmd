# Local or Cloud

## Choose a Mode

| Choose local when | Choose Cloud alpha when |
| --- | --- |
| The task needs a browser or authenticated state on this machine. | You want browser Sessions to run on hosted infrastructure. |

Browser Session and Profile concepts remain consistent across both environments.

## Local Mode

Local mode runs Webcmd against a browser on this machine. Choose it for work
that depends on local browser state or a browser you want to inspect directly.
Self-learning sitemap memory is stored locally.

Configure the local browser with:

```bash
webcmd setup
```

Cloak is the bundled default. You can also select an installed Google Chrome,
the macOS-alpha SLAB runtime, or a compatible browser executable:

```bash
webcmd setup --browser chrome
webcmd setup --browser slab
webcmd setup --browser /absolute/path/to/browser
```

## Webcmd Cloud Alpha

Webcmd Cloud alpha runs browser Sessions on hosted infrastructure with browser
lifecycle, proxying, and live viewport access managed by Webcmd. Cloud access
and credentials are provisioned separately; `webcmd setup` configures local
browser mode only. Hosted browser tasks do not teach or synchronize the local
sitemap memory stored on this machine.

Hosted tasks are scoped to a workspace. Set `--workspace <id>` or
`WEBCMD_WORKSPACE` per invocation; the flag takes precedence over the
environment variable and then the implicit default workspace. Within a
workspace, `--profile <name>` selects an isolated browser identity.

```bash
WEBCMD_WORKSPACE=user_64256 webcmd --profile work session list -f json
```

`webcmd profile list` returns Profiles in the active workspace.
`webcmd profile delete <profile-id>` permanently removes the selected hosted
browser state. When sign-in is required, Webcmd returns a live authentication
view. See [Authentication and Profiles](/authentication-and-profiles).

## What Stays Separate

Local and hosted Profiles, Sessions, site memory, and traces do not sync. Treat
each environment as a separate browser workspace.

Local mode has no workspace concept. An arbitrary `--profile <name>` creates
separate local browser state lazily; `profile list`, `rename`, and `use` manage
that local state.

## Current Boundaries

Cloud is alpha. Billing is not presented as generally available; use it only
when hosted browser infrastructure has been enabled for your account.
