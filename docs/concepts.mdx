# How Webcmd Works

Webcmd gives an agent a live browser plus memory of website structure. The
agent completes the task against the current page while preserving useful,
verified context for the next run.

## The Agent's Decision Flow

1. Create a named browser Session in the requested Profile.
2. Use relevant site memory as a starting point when it is available.
3. Inspect the live page before relying on remembered structure.
4. Navigate, extract, and verify the requested result.
5. Retain useful structural knowledge for future browser tasks.

## Live Pages Stay Authoritative

Memory helps an agent find likely pages, controls, and content regions without
repeating every discovery step. It is guidance, not a recording or a fixed
script. When the page differs from memory, the agent follows the live page and
updates its understanding.

## Profiles, Sessions, and Tabs

A **Profile** is a browser identity and storage boundary, such as `default` or
`work`. Use separate Profiles for accounts or environments that must not share
sign-in state.

A **Session** is a named browser workspace inside a Profile. Sessions allow
separate agents or tasks to work without competing for the same browser window.
Its readable ID is immutable and scoped to its Profile.

```bash
webcmd --profile work session create "Work Project" -f json
webcmd --profile work --session work-project-k7 browser tabs
```

A **tab** is one page inside that Session. Raw browser commands always receive
the Session selector at the root of the command.

## Observe, Act, and Verify

Agents use snapshots to inspect page state and small browser programs to act on
it. An action should be followed by a relevant observation: confirm the URL,
visible state, or extracted fields instead of assuming a click succeeded.

Read-only extraction can usually proceed without interruption. Posting,
purchasing, submitting, deleting, applying, or communicating externally should
follow the approval boundary in the user's request.

## What the Human Needs to Decide

Describe the outcome, required fields, Profile, constraints, and any action that
needs approval. You do not need to describe selectors or browser steps; the
agent determines those from the live website.
